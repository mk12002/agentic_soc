# Failure modes and how the platform handles them

What can go wrong in production, how it shows up, what the platform does, and what was changed to make it
robust. Items marked **fixed** were found in the latest review rounds and are covered by tests.

## External dependencies

| Failure | Detection | Behaviour | Status |
|---|---|---|---|
| **LLM endpoint slow, hung or down** | Call errors and timeouts in the LLM log; `status=error` / `circuit_open` | Connecting is capped at 10 s, so a down endpoint is known quickly. Reads are capped at 30 s for short small-tier answers and 120 s for long large-tier answers; a first version with one 30 s limit broke deep analysis on the real endpoint (caught by the live suite). After 3 consecutive failures a circuit breaker skips the model for 60 s, so screens, reports and answers fall back **instantly** to deterministic, cited text; the next success closes it. Previously a hung endpoint made each call wait up to 120 s, one call after another (an 8-section report could take ~16 minutes). | **fixed** - `test_failing_model_endpoint_trips_the_breaker_and_screens_fall_back_instantly` |
| **LLM throttling / transient 5xx** | 429 / 5xx responses | One retry after `Retry-After` (capped at 5 s), then the deterministic fallback. A real transient error was observed in live measurement and degraded gracefully. | **fixed** - `test_throttled_model_call_is_retried_once` |
| **"Why did the platform (or the AI) do that?"** | Trace view; model-call detail | Before, the access log, audit events, model calls and job runs could not be tied to one request or job, and the evidence check's removals were only counted. Now one trace id links them; each model call keeps its prompt, answer and every removed statement with the reason; structured log lines carry the same id. | **fixed** - `test_observability.py` |
| **A change with no audit record** (a route whose code forgot) | - | Pushed SIEM alerts, for example, left only an access-log row. Every successful write request now leaves at least one audit event (a generic one when the route's code wrote none). | **fixed** - `test_every_successful_write_is_audited_even_when_its_code_forgot` |
| **A burst of AI use** (a script asking questions in a loop, a flood of incidents, a model writing very long answers) | AI usage screen; finding when today's budget is used up | Previously only a monthly cap: a burst could spend the month in a day, and answer length was limited only by the prompt. Now a daily cap (default a tenth of the month), per-person hourly / daily limits and a hard answer cap per call (1,500 small / 3,000 large tokens) apply; refused calls fall back to deterministic text and the person is told why. | **fixed** - `test_llm_usage.py` |
| **Monthly token budget exhausted** | Budget status | A finding is raised at 80 % and at 100 %. After the cap, the deterministic path is used until the month rolls over. The old 5 M default would have run out within days even for a small SOC; it is now 50 M and sized in LLM_TOKENS_AND_COST.md. | **fixed** - `test_budget_alert_and_confirmed_self_check_alerts` |
| **Model writes something unsupported** | Guardrails | Statements without valid citations, statements with figures absent from their evidence, and references to non-existent actions are removed, and the removals are counted. Pseudonym tokens are restored even without brackets. | covered - core/story tests, live LLM suite |
| **Endpoint not on the approved list** | Provider start-up | Refused (fail closed); the platform runs deterministically. | covered |
| **A connector's credentials expire / API down / rate-limited** | Freshness against each stream's cadence ("stale" / "error" on Integrations); job runs | Per-tool budgets, backoff and retry; malformed records are isolated; enrichment reports the source as *unavailable* rather than silently "clean". | covered - connector resilience tests |
| **A vendor API changes its answer shape** | Live tests (`SOC_LIVE_TESTS=1`) | NVD began answering single-CVE lookups with an empty page unless the page size is explicit, so live mode silently lacked NVD scores. Prioritisation falls back to scanner CVSS; the connector now requests the page explicitly. | **fixed** - live NVD test |
| **A connector's token is refused mid-sync** (expired early, rotated, revoked) | 401 | The token is renewed once and the call repeated - in fake mode too (`FixtureTransport` answers 401 the same way). Before, the cached token was reused until its own expiry time, so every call failed meanwhile. | **fixed** - conformance suite, every connector and stream |
| **A permission is missing** (scope not granted, licence tier) | 403; the preflight names the stream refused and the scopes to grant | Stops the stream at once - no retry storm - and says what to grant. | **fixed** - conformance suite |
| **A tool throttles** | 429 with `Retry-After` in seconds or as a date | Waited out (capped at 120 s) and retried; no record lost. The date form used to be ignored. | **fixed** - conformance suite |
| **A proxy, captive portal or SSO page answers instead of the API** | 200 with an HTML body | Reported as "returned an HTML page instead of the API's JSON - check the proxy / allow-list and the base URL", not a cryptic crash; a truncated JSON body is retried. | **fixed** - `test_an_html_page_instead_of_json_is_a_clear_error_and_a_corrupt_body_is_retried` |
| **A sync resumes from an expired continuation token** | - | Graph, Defender, Sentinel, CrowdStrike Spotlight, Rapid7, ServiceNow, Jira, Umbrella and Wiz kept the last page's continuation as the next sync's start: the next sync re-read the last page, failed on an expired token, or (Rapid7) asked for a page past the end and never saw an asset again. Event streams now resume from a time watermark; inventories are read in full. | **fixed** - paging and resume tests per vendor |
| **Logs arrive late, or a device clock is wrong** | - | Resuming exactly from the newest time seen would lose records indexed minutes after the event: the next sync asks from the mark minus 30 minutes (`SOC_WATERMARK_OVERLAP_MINUTES`); re-reads are de-duplicated. A time more than an hour in the future is ignored, or it would move the mark past every real record and silently stop the stream. | **fixed** - `test_late_records_are_caught_by_the_overlap_and_future_times_never_move_the_mark` |
| **A tenant's DNS volume** (tens of millions of queries a day) | - | Umbrella's stream stored every query as a record. It now stores only security-categorised queries (`dns_sync`, the only DNS events any analysis uses); if the category list is unreadable, blocked queries only - never silently everything. | **fixed** - `test_dns_sync_stores_security_activity_by_default_and_never_silently_everything` |
| **Sentinel incidents arrive without their entities** | - | The connector read the incident list only, so every Sentinel incident stood alone, linked to no host or person. It now reads each incident's entities; the demo's two incidents join the existing case. | **fixed** - `test_sentinel_incidents_carry_their_entities` |
| **A vendor timestamp with fractional seconds and an offset** (Jira `.000+0530`) | - | The offset was swallowed into the fraction: 12:00+05:30 read as 12:00 UTC. | **fixed** - `test_jira_times_keep_their_offset` |
| **More than 10,000 CrowdStrike hosts or alerts in one read** | - | Falcon's query APIs refuse offset + limit past 10,000, so a large fleet's inventory, or a first alert backfill, would have stopped there with an error. Hosts are now listed through the scroll query (a continuation token, no limit); alerts restart from the newest update seen when the next page would cross the limit. | **fixed** - `test_crowdstrike_hosts_scroll_by_token_and_are_read_in_full_each_sync`, `test_crowdstrike_alerts_past_the_offset_limit_restart_from_the_newest_update` |
| **CISA KEV or EPSS feed unreachable** | `refresh_intel` result lists `unavailable_feeds`; warning in the log | The intel refresh crashed on the first failed feed, and a KEV answer that came back empty would have cleared every CVE's KEV flag (priorities drop silently). An unavailable feed is now skipped with the last known values kept, KEV is never cleared by an outage, and the CVEs stay due so the next run tries again. | **fixed** - `test_every_tool_down_at_once_degrades_without_crashing` |
| **Reporting mailbox unreachable, or one reported message gone** | Checkpoint `last_error` on Integrations | Ingesting reported e-mails failed the whole phishing job on an outage, read the mailbox from its oldest message every run (at most 5,000, so once it held more, new reports were never reached) and stopped on one unreadable message. It now resumes from its checkpoint with the overlap, records an outage and returns no new reports, and skips an unreadable message (kept for the next run). | **fixed** - `test_every_tool_down_at_once_degrades_without_crashing` |
| **Umbrella down while the shadow-IT screen or a report reads it** | Screen shows "Umbrella unavailable"; report lists the section as skipped | Both crashed. Shadow IT now answers `available: false` with the reason; a report leaves the section out with "source unavailable" and is still produced. | **fixed** - `test_every_tool_down_at_once_degrades_without_crashing` |
| **A connection fails every retry** (DNS, TLS inspection, refused) | Sync report / preflight | The message said only "gave up after N retries"; it now carries the last error's type and text (e.g. a certificate verification failure behind a TLS-inspecting proxy - see CLIENT_DEPLOYMENT_GUIDE §4.17). | **fixed** - `test_a_connection_failure_keeps_its_cause_after_the_retries` |
| **The context store grows without bound** (months of client telemetry) | Retention report `events` | Retention removed copies of source data but kept every event record forever: at hundreds of thousands of sign-ins a day, every table and index would keep growing. Telemetry events older than `SOC_EVENT_RETENTION_DAYS` (400) are now pruned with everything attached to them, unless a case, evidence, an insight or an override still refers to them. | **fixed** - `test_old_telemetry_is_pruned_unless_something_still_points_at_it` |
| **A brand-new or empty tenant** | - | Every pipeline, read model, report, the brief and the self-check run with zero records. | covered - `test_an_empty_tenant_runs_every_pipeline_screen_and_report` |
| **A record misses a field or has a null** | Sync report (failed count, reason) | 14 connectors crashed on some missing or null field (KeyError / TypeError). Optional fields are now tolerated everywhere; a record without its identifier is refused with "record without its identifier 'id'" and counted as failed. | **fixed** - every field of every record of every stream, removed and nulled |
| **A record has a field of the wrong type** (an object where text belongs, one object instead of a list, a number as text, `"N/A"` for a list) | `connector.data_quality` log line per sync: which fields, how often | A fuzz of every parser with wrong-typed fields crashed **715** ways across **26 of 27** streams (`'str' object has no attribute 'get'`), and each crash set the whole record aside. Records are now brought to the vendor's documented shape - learned from the connector's own fixtures - before they are parsed: the record is kept, only the unreadable field is emptied, and the coercions are reported so a vendor change is visible. Numeric ids are accepted as text. Only a record whose identifier is unusable is refused, with the reason. | **fixed** - `test_wrong_typed_fields_never_crash_a_normaliser` (every field of every stream, 11 odd values), `test_a_sync_keeps_records_with_malformed_fields_and_reports_them` |
| **A vendor time from the future, a placeholder date or an odd epoch** | Record keeps `reported_time` | A record dated `9999-12-31` (or from a device whose clock is years ahead) became the store's latest observation, the "now" every risk score decays from - every real signal would have looked decades old. .NET's `0001-01-01` "no value" was stored as year 1; an out-of-range epoch raised an error (and a negative one does on Windows); an epoch sent as text was lost. Now: times more than 24 h ahead are stored as seen now with the vendor's value kept, dates before 1990 count as no time, out-of-range epochs read as no time, epoch text is read. | **fixed** - `test_vendor_times_are_read_or_treated_as_absent_never_raised`, `test_a_time_far_in_the_future_is_stored_as_seen_now_and_does_not_skew_risk` |
| **A SIEM pushes a batch with one malformed alert** | Push response `rejected` + `reasons`; `ingest.rejected` log line | One alert without an id failed the whole request, so a SIEM that retries would resend the batch forever and no alert of it would land. Alerts are now isolated like sync records: the rest land, the bad ones are refused with their reason. | **fixed** - `test_one_malformed_pushed_alert_is_refused_and_the_rest_of_the_batch_lands` |
| **The ownership spreadsheet is saved the way Excel saves it** | Warning when it has no hostname or subscription column | UTF-8 with Excel's byte-order mark made the first column `\ufeffhostname`, so no row matched and no asset had an owner - silently. Windows-1252 files raised an error; semicolon-separated files (European Excel) read as one column; `Host Name` / `Owner Email` headers were not recognised; the file was opened without being closed (locked on Windows) and re-read on every lookup. Now every one of those is read, headers are matched in any case or common alias, and the file is re-read only when it changes. | **fixed** - `test_the_ownership_file_is_read_however_excel_saved_it` (4 encodings / separators), `test_the_ownership_file_is_re_read_only_when_it_changes` |
| **The model answers in an unexpected shape** (a list where a word belongs, a number for a list, broken JSON) | Model-call log | Model output is untrusted input. A list for `kind`, `status` or `confidence`, a number for `claims` or `evidence_ids`, or a list as the report planner's `days` crashed the answer, the deep analysis or the report plan; `"insufficient_evidence": "false"` read as true; a planned report could ask for 99,999,999 days. Every field is now read defensively: a malformed item is dropped (and counted with the other removed statements), a period is kept within 1-730 days, and an answer with nothing usable falls back to the deterministic one. An analyst tool that the database refuses runs in its own savepoint, so on PostgreSQL it no longer aborts the rest of the request. | **fixed** - `test_grounded_answers_survive_any_shape_of_model_answer`, `test_planners_survive_any_shape_of_model_answer`, `test_deep_analysis_survives_any_shape_of_model_answer` |

## The platform itself

| Failure | Detection | Behaviour | Status |
|---|---|---|---|
| **One connector misconfigured** (secret missing, entry invalid, constructor or action factory failing, module not importing) | Integrations: state *misconfigured* with the reason | Used to raise `ConfigError` out of the action registry and stop phishing, incident and vulnerability handling and the approvals screen. The connector is now isolated - left out of every workflow, its recommendations shown as manual steps - and every other tool keeps working. | **fixed** - `test_one_misconfigured_connector_is_isolated_and_everything_else_keeps_working`, `test_a_connector_that_cannot_be_built_is_isolated_with_the_reason`, `test_a_connector_module_that_fails_to_import_is_left_out` |
| **A typo in the connector configuration** (tool name, key, stage, setting, value) | `config check`; start-up error; console refusal | Was ignored silently: a misspelled tool never ran, `enabeld: false` left a tool on. Now every problem is named with its fix ("did you mean ...?"); `serve` / `scheduler` refuse to start on file errors; a console change with one is refused. | **fixed** - `test_every_problem_in_a_configuration_is_named_with_how_to_fix_it`, `test_serve_refuses_a_broken_configuration_and_says_how_to_fix_it` |
| **A tool promoted to live before it works** (wrong URL, credentials, permissions, proxy, clock) | Preflight on the proposal | The proposal is refused with the checklist and each fix; the approval refuses a preflight that no longer matches (a secret removed meanwhile) or is over 7 days old. | covered - preflight and governance tests in `test_connector_admin.py` |
| **Two configuration changes in flight** | Approval | The later one, made against an older version, is refused ("propose it again") instead of silently undoing the other. | covered - `test_a_stale_proposal_cannot_overwrite_a_newer_approved_change` |
| **A tool misbehaves in production** (floods alerts, wrong actions) | Analysts | *Pause* switches it off at once (audited, reason required) on every process within seconds; actions it would have taken become manual steps; switching it back on is approved. | covered - `test_pausing_is_immediate_and_resuming_needs_approval` |
| **A configuration change must be undone** | History | *Restore* proposes any earlier version; export / import keeps a copy outside the platform. | covered - restore and round-trip tests |
| **Scheduler stops, hangs or is never started** | `/health` → `scheduler.state` (`running` / `stuck` / `stale` / `never`); a **"Scheduler stopped"** or **"Scheduler stuck (job)"** banner on every screen | The scheduler used to be a second process that had to be started and kept running; forgetting it meant no jobs. It now runs inside the API server, so starting the platform starts it. It is self-healing: an error in a pass is logged and the next pass runs, and a stopped thread is restarted. A heartbeat thread writes every 30 s whatever the jobs are doing, so a long job never looks like a dead scheduler, while a job running past its 30-minute lease is reported as *stuck*. A heartbeat write that is only waiting for the database (SQLite blocks writers during a long transaction, e.g. a slow LLM call in a demo) no longer shows "Scheduler stopped": the server asks its own in-process scheduler whether it is alive. | **fixed** - `test_scheduler.py`, `test_health_reports_a_stopped_scheduler` |
| **A job keeps failing** | Job history; Teams / Slack when notifications are configured | Retries with backoff; after 3 failed runs it is dead-lettered and a finding is raised (and sent to the notification channels). It can be replayed from Integrations. | covered |
| **The ML engine calls out to external services** | Test with all network access blocked | The engine read the project's .env itself: image attachments went to an Azure OCR service, e-mail URLs and hashes to public lookup services. Offline mode now clears every lookup switch and credential on its live settings. | **fixed** - `test_the_engine_makes_no_outbound_connection_in_offline_mode` (3 attempts before, 0 after) |
| **Notification webhook down or rejecting** | Integrations → *Notifications* (status, error, attempt n of 5) | The delivery is recorded as failed and retried every minute, up to 5 attempts; other channels and the job that raised the finding are unaffected. An invalid or non-HTTPS webhook entry is skipped with a warning at start-up, never a crash. | covered - `test_notify.py` |
| **LLM slow while cases arrive** | LLM latency per workflow (`/api/v1/llm/status`) | The incident and phishing jobs commit each case (verdict, evidence, recommendations) before asking the model; explanations for the batch follow in parallel. A slow model delays only the written explanation. If a run stops in between, the next run finishes the pending explanations. | **fixed** - deferred narration tests |
| **Several schedulers, restarts** | Job history | The database decides what is due: a job runs when no run of it, by any scheduler, started within its interval. A restart does not re-run every job, and two servers do not run the same job back to back. The lease is held until the run is recorded, and whether the job is still due is checked again once the lease is held; that closed a race found by testing two schedulers at once. Taking a lease is a compare-and-swap, and when two schedulers take a job's first-ever lease together exactly one wins; the other skips (it used to crash its pass). The heartbeat's first write is safe the same way, and the heartbeat and job threads merge into the latest version of their shared row, so the "running job" shown is never an older one. | **fixed** - `test_two_schedulers_at_once_never_run_a_job_twice` (repeated 28×), `test_first_leases_taken_at_the_same_moment_have_one_winner_and_never_raise`, `test_the_heartbeat_never_puts_back_a_stale_running_job`; scheduler tests fail on any background-thread exception |
| **Pipelines or jobs run twice** (restart, replay, overlap) | Self-check "one case per reported email", "no duplicate active campaigns" | Everything is idempotent. Previously a re-pull of the reporting mailbox created a second case per email (doubling risk scores), and a second campaign per CVE notified owners twice. | **fixed** - `test_rerunning_every_pipeline_and_job_changes_nothing` (3 estates) |
| **A write is acknowledged before it is committed** | Real-server read-after-write test | FastAPI ended each request's database session after sending the response, so an uploaded report's case was missing from the next case list in 28 of 40 tries, and a commit failure would have reached the client as success. Every request now commits (or rolls back) before the response is sent. | **fixed** - `test_commit_before_response.py` (every route checked; 15 uploads read back from a real server) |
| **A domain-scoped user opens a screen outside their scope** | Browser tour signs in as a phishing-only analyst | The menu already hid the screen, but a typed-in or shared address loaded it and every call was refused (error pop-ups). The console now says which scope the screen needs instead of calling the API. | **fixed** - browser tour |
| **Figures drift between screens** | Hourly **platform self-check** | Recomputes each shared figure through every code path and resolves every reference. A finding is raised only if a check fails **twice** in a row, so commits landing between counts cannot cause false alarms. | **fixed** - self-check tests |
| **Large tenant slows the screens** | `scripts/measure_scale.py`, `scripts/load_test.py` | The risk ranking and the correlation job profiled every user and host; they now profile only entities with a risk source (0.06 s at 20,000 entities when few have activity). On a realistic estate nearly every user and host has activity: the ranking (brief, Intelligence screen) took **9.4 s per request** at 21,728 entities. It is now reused while the data it reads is unchanged - exact (a fingerprint of those tables plus a counter every local write bumps): **4.7 s once, then 0.02 s**; the brief **9.4 s → 0.03 s**. The case page's shared-action lookup is narrowed in the database: **0.47 s → 0.005 s** at 20,000 executed actions. | **fixed** - `test_risk_ranking_only_profiles_entities_with_risk_sources`, consistency suite |
| **Ingestion slows as the estate grows** | Statements per synced record (`measure_scale.py`) | Three hotspots grew with the estate: each new host loaded every host behind the company's NAT address (165 statements per host at 60 hosts, **1,846 at 600**), 50 arbitrary hosts sharing its name prefix (in no fixed order), and the entity lookup every record makes scanned all entities of its kind (SQLite chose the wrong index). Now flat: candidates are selected exactly (nameless, in-window, by an indexed range), and a (kind, canonical key) index is added - also to existing databases at start-up. Sync at 40x: **244 s → 149 s**, statements per record unchanged; matching results identical (0 false merges, same splits). | **fixed** - `test_volume.py` |
| **A large sync on PostgreSQL** | Sync error "out of shared memory - increase max_locks_per_transaction" | A whole sync was one transaction with a savepoint per record; each savepoint holds a lock until the end, and tens of thousands ran PostgreSQL's lock table out (SQLite never shows this). Now one savepoint per page and a commit per page; a page that fails is replayed record by record, and 20 identical failures in a row stop the replay (a systematic fault, e.g. a query the engine rejects). | **fixed** - `test_a_sync_takes_one_savepoint_per_page_not_per_record`; measured on PostgreSQL at 40x |
| **A backfill is interrupted** (timeout, restart, network) | Sync report / job history | The checkpoint was only flushed, so a failure rolled back every page read so far and the next run restarted from zero - a first backfill that always ran out of time never finished. Pages are now committed as they are stored; the next run continues after the last one. A backlog beyond `SOC_SYNC_MAX_PAGES` continues on the next sync (`truncated`). | **fixed** - `test_an_interrupted_backfill_keeps_its_pages_and_resumes_after_the_last_one` |
| **Downloads outrun ingestion** | - | Parallel stream downloads queued every page in memory. The queue is now bounded (8 pages per stream); a stopped ingestion drains it, so a download never blocks forever. | **fixed** - `test_parallel_downloads_stay_a_bounded_distance_ahead_of_ingestion`, `test_ingestion_stopping_early_never_leaves_a_download_blocked` |
| **The review queue floods** (large fleet) | Overview → *Awaiting resolution* | DNS events naming a host that shares its name with another machine all went to review (106 of 142 items on a 130-person estate), though the event's IP pointed at one of them. An event is now attached when the host has the exact name, an in-window IP match and a clear margin (it links an event, it never merges). The automatic-match threshold is a setting (`SOC_RESOLUTION_AUTO_THRESHOLD`) to decide on shadow-mode results. | **fixed** - `test_a_dns_event_naming_a_host_with_a_namesake_links_by_its_ip_instead_of_queueing` |
| **Many analysts at once** | `scripts/load_test.py` (real server) | One server process served 43 requests/s and every request queued behind the others (276 ms for `/health`). `SOC_API_WORKERS` runs several processes (the image runs 4): 128 requests/s to 40 analysts with medians of 5-56 ms, 150 requests/s to 100 analysts with no error. | **fixed** - `test_many_analysts_at_once_on_a_real_multi_process_server_get_no_server_error` |
| **Database saturated, locked or unreachable** | 503 with `Retry-After` | All connections busy (pool sized by `SOC_DB_POOL_*`), SQLite still locked after its busy timeout, or the database briefly gone now answer 503 so the client retries; before, the request hung 30 s and answered 500. Connections are checked before use and recycled, so a failover or a firewall dropping idle connections does not surface as errors. | **fixed** - `test_a_saturated_or_locked_database_answers_retry_later_not_a_server_error` |
| **Lists longer than 500 rows** | - | Badges and tabs use true totals (summary endpoints); lists filter by domain on the server. The case and approval lists stopped at the 500 most recent, so older cases could only be reached by search; they now page (`?offset=`, *Older* / *Newer*), newest first with ties broken by id so pages never overlap or skip. | **fixed** - `test_case_and_action_lists_page_without_overlap` |
| **Database rejects a value (PostgreSQL only)** | Full suite on PostgreSQL; the SQLite suite enforces the same rules | SQLite ignores column widths and accepts NUL characters; PostgreSQL rejects both, and the whole write fails. Found by running the suite on PostgreSQL:<br>• a manual job run by a user with a long e-mail address failed, because the run's trigger column was 32 characters<br>• an id containing `%00` answered 500 on 20 routes<br>• a NUL character in a reported e-mail's body would have failed the write of its case<br>Now:<br>• free text from vendors and people (titles, subjects, names, user agents) is kept to its column width<br>• NUL is stripped from every text value before it is stored<br>• NUL in a URL is refused with 400<br>• any other value the database cannot store answers 400, not 500<br>• start-up widens PostgreSQL columns that the model has made longer<br>Identifiers are never shortened: a mismatch there fails loudly. | **fixed** - `test_input_postgresql_would_reject_never_crashes_a_request`, suite on PostgreSQL |
| **Old items vanish from a figure as time passes** | Time-travel tests | The dashboard counted approvals only among actions created in its 14-day window. An approval still waiting after 15 days disappeared from the dashboard and the reports, while the queue and the analyst still showed it. Now the whole backlog is counted, scoped to the viewer's domains like the queue. | **fixed** - `test_retention_prunes_old_mail_but_keeps_open_cases`, scoped-viewer consistency check |
| **Risk fades while the problem is still open** | Time-travel tests | Risk decays with a 7-day half-life. That was applied to everything, including KEV exposure that is still open and incidents that are still open, so an unpatched host slowly "became safe". The "privileged user at risk" amplifier did the opposite: it never faded. Now:<br>• open exposures and open incidents count in full until they are closed<br>• activity (alerts, sign-ins, clicks) decays<br>• amplifiers fade with the activity that triggered them | **fixed** - `test_activity_decays_by_half_every_half_life_but_open_exposure_does_not` |
| **Failures hidden by silent error handling** | Linting, repository-wide | 40 places caught an error and carried on without a trace. Three of them hid problems an analyst needs to see:<br>• the break-glass alert could fail unnoticed<br>• enrichment records could fail to store<br>• a failed threat-intel lookup looked like "nothing found"<br>The correlation job's drift and supplier rules also returned "no findings" when they had crashed. Every one now logs: a warning for real failures, debug for expected best-effort cleanup. The resilience catches that remain are marked with their reason. | **fixed** |
| **Phishing actions that did less than they reported** | Code review, linting | • The warning-banner action logged "applied" but never changed the message. Graph lets only drafts be edited, so a delivered message is now tagged with a visible "Security warning" category, and the result says which happened.<br>• Threat-intel search ignored its minimum-severity parameter.<br>• IOC first- and last-seen times were converted to the server's local time but labelled UTC: 5½ hours wrong on a machine in India.<br>• An upload handler blocked the event loop while writing files.<br>• A CSV export was opened and never closed, which keeps the file locked on Windows. | **fixed** - graph action tests |
| **All feeds stop** | Integrations shows each connector as stale | The risk engine measures "now" from the latest observation, so replayed or historic data decays sensibly. If every feed stops, scores freeze at their last values instead of decaying to zero. That is deliberate: silence is not safety. The stale connectors and the scheduler heartbeat are what alert. Phishing factors are dated when the platform processed the report. In production that is minutes after delivery; the e-mail's own `Date` header is not used, because an attacker controls it and could backdate a message to make it fade. Because scores move with the clock, tests that compare two runs figure-for-figure freeze the clock (`SOC_CLOCK_FREEZE`, test-only): under load, one run's later clock once rounded a score differently. | by design - documented |
| **Timestamps read in the wrong time zone** | - | All timestamps are stored and returned as UTC with an explicit offset; the UI says "All times UTC". | **fixed** |
| **Malformed input / unknown ids** | - | Every write route is fuzzed and every unknown id answers 4xx. Unknown incidents and campaigns used to answer 500. A fuzz driven by the API's own schema (every field of every request body given 12 odd values, every query parameter of every GET route 8) found two more: an oversized number in the access-log and audit-export filters overflowed the database integer (500); both are now bounded (422). | **fixed** - route sweep + fuzz tests |
| **A mistyped setting** (`SOC_API_WORKERS=four`, `SOC_ENVIRONMENT=production`, an unknown or misspelled `SOC_*` name) | `config check`; start-up refusal; `settings.problem` log lines | The first unreadable value stopped the start with a bare conversion traceback, others were read only later (a crash mid-request), and a misspelled name was silently ignored. `serve` and `scheduler` now check every setting first and list each problem with its fix; an unknown name is reported with the nearest real one; production refuses dev sign-in, MFA off and no encryption key. | **fixed** - settings tests in `test_data_tolerance.py` |
| **A policy document with a value of the wrong type** (autonomy or AI usage policy) | Proposal refused with every problem | The autonomy policy checked only each action's level: `"default_level": "abc"`, a list in place of the actions map or a misspelled key passed validation and four-eyes approval, after which **every** action decision would have failed. VIP lists given as one name were matched letter by letter. The AI usage policy validator itself crashed on a list where a map belongs and accepted an infinite price. Both now reject every wrong type with its fix; a stored policy written before this decides at L2 (recommend), four-eyes, for an unreadable entry instead of failing. | **fixed** - `test_any_wrong_value_in_an_admin_document_is_rejected_with_a_reason_never_a_crash` (every node of the autonomy policy, AI usage policy and connector configuration, 13 odd values), `test_an_autonomy_policy_with_a_wrong_type_is_not_saved_and_a_stored_one_fails_safe` |
| **A reported e-mail that cannot be read reliably** (UTF-16, NUL bytes splitting words and links, no sender, damaged MIME, invalid base64) | Evidence "Could not be read reliably: ..." on the case | The parser recovered and the analysis saw less than the message holds - some such messages came out *safe*. UTF-16 is now decoded and NUL bytes removed before analysis (both are filter-evasion tricks), and any message with a structural defect, no sender or no readable content is never called safe or spam: it is held as suspicious for an analyst with the reason as evidence. The labelled corpus verdicts are unchanged. | **fixed** - `test_a_message_that_cannot_be_read_reliably_is_never_called_safe` |
| **A deploy or `docker stop`** (SIGTERM) | `server.stop` log line | The scheduler service ignored SIGTERM and was killed mid-job; the server never wrote its last queued access-log rows; one slow request could hold a shutdown until the orchestrator killed the process. The scheduler now stops between jobs, the server flushes the access log, and requests in flight get `SOC_SHUTDOWN_GRACE_SECONDS` (20) to finish - inside compose's 30 s `stop_grace_period`. | **fixed** - `test_the_scheduler_service_stops_cleanly_on_sigterm`, `test_stopping_the_server_writes_the_last_access_log_rows_first` |
| **A runaway query on PostgreSQL** | Statement cancelled by the database | Nothing bounded a single statement: one pathological query could hold a connection and its locks until noticed. `SOC_DB_STATEMENT_TIMEOUT_SECONDS` sets PostgreSQL's `statement_timeout` on every connection (0 = off by default, so a first large backfill is never cut short; 120 recommended once steady). | **fixed** (opt-in) - `test_postgres_connections_carry_the_statement_timeout` |
| **Several processes call one tool** (API workers + scheduler service) | - | Each process held its own copy of a tool's request budget, so with 4 workers and a scheduler the vendor could see 5x the configured rate. `SOC_CONNECTOR_RATE_SHARE` (5 in the compose file) gives each process 1/N. Throttling answers (429 with `Retry-After`) are waited out in any case. | **fixed** - `test_processes_calling_a_tool_split_its_request_budget` |
| **Cross-domain data exposure** | - | The audit and access logs were readable across domains; they are now scoped. Every GET route is swept as 7 roles on 3 estates. | **fixed** |
| **Encryption key missing / rotated** | Start-up in prod | Fails closed without `SOC_DATA_KEY` in prod; rotation keeps old keys for decryption. | covered |
| **Identity provider outage** | - | Sealed break-glass access, audited and alerted. | covered |
| **Automation misbehaves** | - | Kill switch (durable, all replicas); actions are idempotent, pre-conditions are re-checked, reversible actions roll back. | covered |
| **Audit tampering** | `/api/v1/audit/verify`, hourly self-check | The hash chain breaks at the edited record. | covered |

## Remaining risks (need the client's environment)

- **Real volumes:** load not yet tested at the client's scale. Mitigation: the scaling fixes above, a stateless API,
  leased jobs and PostgreSQL. Measure with production data before go-live.
- **Live connector behaviour:** each connector must be tested against the client's tenants. Live mode is exercised
  only for the public feeds and the LLM.
- **Accuracy on the client's data:** measured by shadow mode and drift monitoring once live.
- **Record shapes the fixtures do not show:** malformed fields are now tolerated against each stream's documented
  shape, but a field the vendor sends that the fixtures never contained is passed through unchecked. Record and
  sanitise real responses during deployment (OPERATIONS.md) so the fixtures - and so the shapes - match the tenant.
